# 本地安全回归与更新验收

需要 macOS、Xcode 命令行工具和 Python 3。以普通用户运行：

```sh
bash Tests/run-security-tests.sh
```

测试使用 `/private/tmp` 临时目录，结束后清理。不会联网、启动内核、安装 helper、修改持久偏好设置或写入系统服务目录。

| 范围 | 验证内容 |
| --- | --- |
| 文件与协议 | SHA256、大小限制、路径穿越、符号链接、FIFO、旧启动协议和缺失字段 |
| Alpha 下载 | 官方 JSON 字段、资源选择、校验清单、摘要、架构、gzip 损坏和膨胀、HTTPS 重定向、取消、超时和迟到回调 |
| 本体更新 | 菜单目标、移除隐式更新器及依赖、中文提示；提取实际菜单方法，使用内存提示框测试历史自动更新设置、版本字符串和重复点击 |
| 存储与日志 | 原生产源码的只读 root 策略；隔离目录中的原子发布、ACL、缓存篡改、配置权限、保留旧 Alpha、日志定时截断和会话清理 |
| helper 兼容性 | 编译实际管理器的版本、能力、连接、超时和安装状态逻辑，使用离线 XPC、UI、时钟和安装替身 |
| 构建信任清单 | 调用真实生成脚本验证摘要、幂等性、损坏 gzip、特殊路径和异常输出目标；失败时保留已有清单 |

存储的写入测试会复制生产源码到临时目录，仅替换根路径、预期 UID/GID 和私有成员可见性，以便普通用户验证实际文件操作。原文件不变。helper 测试替换外部依赖，不执行真正的授权安装。上述测试不等同于管理员安装、真实 XPC 调用、在线 Alpha 下载或 TUN 启停的实机验收。

构建双架构应用后，可只读检查产物：

```sh
python3 Tests/verify-release-artifact.py '/path/to/ClashX Meta.app'
```

这会检查主程序和 helper 的架构与签名完整性，确认产物没有 Sparkle 框架、链接和更新配置，并检查编译后的菜单和中文提示。它不启动应用，也不证明发布者身份可信。

本体更新固定显示“已是最新版本”，不访问上游应用发布源；Alpha、订阅和 GEO 数据更新仍保留。XPC 客户端身份验证是独立的待处理事项。
